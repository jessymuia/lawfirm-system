# Upgrading to 1.0.0 (from 1.0.0-rc.1)

## Before you upgrade

- Take a backup: `php artisan app:upgrade --backup` does it for you and stops if the backup fails.
- Make sure the scheduler runs every minute (`php artisan schedule:run`, or the bundled `scheduler` container/CronJob). Several features now depend on
  it: `health:probe`, `webhooks:deliver`, `support:expire`, `retention:run`, `billing:run` (multi-tenant), `tenants:usage`. Without it the status page reports the scheduler as down.
- Bare-metal installs that deploy with `git fetch && git reset --hard` must convert once to the release-directory layout: docs/ops/UPGRADE_ROLLBACK.md.
- Multi-tenant (SaaS) operators: platform staff must have an authenticator app ready (see below).

## What changes

- **Security headers (SEC-14).** Every response now carries HSTS (on HTTPS only, one year, including subdomains), a Content Security Policy in **report-only** mode and a Permissions-Policy. Before upgrading, check that every subdomain of your host serves HTTPS, or set `SECURITY_HSTS_INCLUDE_SUBDOMAINS=false` (or `SECURITY_HSTS_MAX_AGE=0` to send no HSTS). Behind a TLS-terminating proxy, set `TRUSTED_PROXIES` or HSTS is not sent. With direct uploads, add the bucket's origin to `SECURITY_CSP_CONNECT`. Watch the log for `csp violation` entries, then set `SECURITY_CSP_MODE=enforce`. New public route `POST /api/v1/csp-report`. See docs/security/SECURITY_HEADERS.md.
- **Malware scanning of uploads (SEC-14).** Off by default. To turn on, run clamd (e.g. the `clamav/clamav` image) with `StreamMaxLength` at least your largest upload, and set `DOCUMENTS_MALWARE_SCAN=clamd`, `CLAMD_HOST`, `CLAMD_PORT`. While clamd is unreachable uploads are refused with a 503 unless `DOCUMENTS_MALWARE_FAIL_OPEN=true`.
- **Automatic card payment (PLAT-4), multi-tenant only.** Control-plane columns on `subscriptions` (Stripe customer, saved payment method, card label, `autopay`) and `billing_invoices` (attempt count and time). Nothing is charged until a firm saves a card through the link staff send it. Add `payment_intent.succeeded` to the events your Stripe webhook endpoint sends (with `checkout.session.completed`).
- **Legacy databases need a signed-off mapping (CARRY-4).** Only affects installs still on the pre-2026 schema (invoices without `workflow_status`): `app:upgrade` now stops if the database holds a status, archive or enum value not in `config/legacy_mapping.php`. Run `php artisan migration:status-report` to see which, add them to the mapping (or fix the data), then upgrade. Already-upgraded installs are not affected. See docs/ops/LEGACY_CUTOVER.md.
- **Stronger password resets (SEC-14).** A reset password needs at least 10 characters with letters and numbers, as at signup. Existing passwords keep working. Laravel moves to 12.69.3 (`composer install` from the lockfile).
- **Monthly restore drill (CARRY-7).** The scheduler runs `backup:drill` on the 1st of each month at 05:00. It needs the same `mysql`/`gunzip`/`tar` tools as `backup:run`, room for a second copy of the database on the same server for a few minutes, and a database account allowed to create and drop databases named `drill_*`. Route its `critical` log entries to alerting. Run it once by hand after upgrading and keep the time it reports.
- **Redis cache flush is per firm (TEN-10).** With `CACHE_STORE=redis`, `cache:clear` / `Cache::flush()` now deletes only the active firm's keys (or, on a single-firm install with a cache prefix, only keys under that prefix) instead of the whole Redis database. To empty a Redis database on purpose, use `redis-cli -n <db> FLUSHDB`.
- **Asking firms for payment (PLAT-4), multi-tenant only.** Nothing changes until the platform's accounts are configured. Card: `STRIPE_SECRET_KEY` (the platform's account; the webhook secret is unchanged). M-Pesa: `MPESA_CONSUMER_KEY`, `MPESA_CONSUMER_SECRET`, `MPESA_PASSKEY`, `MPESA_ENVIRONMENT` next to the existing `MPESA_SHORTCODE` and `MPESA_CALLBACK_TOKEN`, then run `php artisan billing:mpesa-register` once. New routes on the platform host only: `GET /api/platform/pay/{number}`, `POST /api/platform/webhooks/c2b/{token}`, `POST /api/platform/webhooks/stk/{token}/{number}`, `POST /api/platform/billing/invoices/{number}/mpesa`. Try both in Stripe test mode and the Daraja sandbox before going live. See docs/BILLING.md.
- **Traces and error tracking (ENG-24).** Off until configured; nothing changes on upgrade. To turn on: `OTEL_EXPORTER_OTLP_ENDPOINT` (OpenTelemetry collector or vendor endpoint, plus `OTEL_EXPORTER_OTLP_HEADERS` for its key) and `ERROR_TRACKING_DSN` (Sentry, GlitchTip or Bugsink). Error messages can quote data, so host the tracker where firm data may live. See docs/OBSERVABILITY.md.
- **Per-firm restore (TEN-14), multi-tenant only.** New control-plane table `tenant_restores`. The scheduler now runs `tenants:snapshot --all` nightly (01:45) and `tenants:restore-drill` weekly (Sunday 04:00); on a self-hosted install both do nothing. For point-in-time restores, keep the MySQL binary log on with `binlog_format=ROW` for the window you promise. Give the database account `RELOAD`, `REPLICATION CLIENT` and `REPLICATION SLAVE`. Install `mysqldump`/`mysqlbinlog` where the scheduler runs (the Docker image has them). Turn on versioning for S3 buckets that hold firm files. Route critical log entries from snapshots and drills to alerting. See docs/ops/FIRM_RESTORE.md.
- **Retention classes (SEC-13).** `retention_disposals` gains `record_type` and `record_id`, and its `document_id` becomes nullable. New classes `matter_emails`, `portal_messages` and `inactive_clients` do nothing until a firm sets a period and turns automatic disposal on for them. Existing document policies are unchanged. `retention:run` now reports one line per class. `GET /compliance/retention/due` takes `?class=`, and its answer adds `record_class` and `ids` (`document_ids` is kept for documents).
- **Currencies and tax rates join the system catalog (TEN-11).** The upgrade adds the catalog currencies (disabled, except the base currency, which is always available) and Kenyan VAT rates to every firm. VAT 16% becomes the default tax rate where a firm has none. A firm's own tax rate with the same name and jurisdiction is adopted rather than duplicated. Firms outside Kenya should archive these rates and add their own.
- **Currencies and tax (DATA-14).** New tables `currencies`, `exchange_rates` and `tax_rates`, plus nullable columns on `invoices` and `invoice_items`. `app:upgrade` (and the fleet migrator) queue `BackfillInvoiceFx`, which gives issued invoices in the base currency rate 1; run a queue worker, or keep the default `sync` queue. The base currency defaults to `MONEY_BASE_CURRENCY` (`KES`); a firm can change it under Settings → Currencies and tax until it issues an invoice. **An invoice in a currency other than the base currency now needs an exchange rate before it can be issued.** New permission `manage-finance-settings` is added to the built-in `admin` role. The invoice line form no longer adds 16% by itself; it uses the firm's default tax rate, which the system catalog (TEN-11) provides. See docs/MONEY.md.
- **Branding (UI-13).** New permission `manage-branding`, added to the built-in `admin` role (custom roles are not changed). The web app shows the firm's name from Settings → Branding (default: `APP_NAME`) instead of a fixed name: set `APP_NAME` or the branding name before upgrading if you relied on the old text. New public endpoints `GET /api/v1/branding` and `/api/v1/branding/logo` (name, colour and logo only).
- **Enums and matter types (DATA-12).** New table `case_types` and nullable `cases.case_type_id`. `app:upgrade` (and the fleet migrator) queue `BackfillCaseTypes`, which builds the list from existing matters; run a queue worker, or keep the default `sync` queue. On MySQL/MariaDB/PostgreSQL the migration adds a CHECK on `tasks.priority` and **stops if any task has a priority other than `high`, `medium` or `low`**: find them with `select id, priority from tasks where priority not in ('high','medium','low')` and fix them first. Code that writes an unknown status, priority, payment method or trust entry type (custom scripts, imports) now gets an error instead of a stored bad value. See docs/DATA_ENUMS.md.
- **Per-firm encryption (TEN-13), multi-tenant only.** New control-plane table `tenant_keys`; nothing changes until `TENANCY_MASTER_KEY` is set (`php artisan tenants:keys --generate-master-key`; keep it in your secret store with a backup, like `APP_KEY`). Then run `php artisan tenants:keys --all --enable` once to give existing firms their keys and re-encrypt their stored secrets. From then on, tenant backups are written as `*.gz.enc`: restore with `tenants:decrypt-backup` first. `App\Tenancy\Keys\EncryptionKeyPurgeStep` joins `tenancy.purge_steps` by default; if you list your own steps, add it. See docs/ops/FIRM_ENCRYPTION.md.
- **Accessibility (UI-15).** No schema change. The app's blue and its grey secondary text are slightly darker so they meet WCAG AA. A firm whose brand colour is light sees a darker shade of it for text and buttons; the installed app's theme colour is unchanged. The end-to-end suite now needs `@axe-core/playwright` (`cd tests-e2e && npm ci`).
- **Firm switcher (UI-16).** New control-plane table `firm_switch_tokens` (multi-tenant; nothing to do on single-firm installs). New web route `/switch/{token}`: if a reverse proxy only forwards `/api` and the app shell, let it through.
- **Multi-tenant only: everyone is signed out once.** Sessions are now per firm (the cookie name includes the firm), which closes a cross-firm session replay (see the Security entry in the changelog). Self-hosted single-firm installs keep their existing sessions. If you use the file session driver, firm sessions live in a sub-directory per firm.
- **Platform staff MFA is required by default** (`PLATFORM_MFA=required`). Staff without MFA can sign in only to enrol. Set `PLATFORM_MFA=optional` to postpone it.
- **Bulk delete of clients and matters is now all-or-nothing.** If any selected record is under legal hold or fails a check, nothing is deleted and the response says why. Integrations that relied on partial success must retry the remaining records.
- **New permissions** are added to the built-in `admin` role automatically: `manage-ethical-screens`, `access-all-matters`, `manage-matter-access`, `manage-support-access`,
  `manage-security-settings`, `manage-compliance`, `manage-api-access`. **Custom roles are not changed**: grant them where wanted.
- **Courts, court types and hearing types become system reference data (TEN-11).** The upgrade adds the platform's catalog to every firm. Existing rows with the same name are adopted, keeping their ids. From then on firms cannot rename or delete those rows (the API returns 409 `system_catalog`), but they can set a local name (`alias`). Their own rows are unaffected. Integrations that rename or delete seeded court/hearing types must send `alias` instead. `php artisan catalog:sync --dry-run` shows what will change. See docs/SYSTEM_CATALOG.md.
- **Public ids (DATA-9).** `clients`, `cases` and `hearings` gain a nullable `public_id`. The upgrade queues a job that fills it for existing records; run a queue worker, or keep the default `sync` queue, so the job actually runs. Public API and webhook ids become ULIDs (the public API has not shipped in a release yet, so no integration depends on integer ids).
- **Firm-wide export is queued (ENG-21).** Run a queue worker (or keep the default `sync` queue) so exports are built; the scheduler must run `exports:prune`. Integrations calling `GET /api/v1/export/firm-data` keep working but should move to `POST` + status polling.
- **List endpoints always paginate (ENG-16).** A call without `?page=` now returns page 1 (`data.data`, up to `per_page`, max 100) instead of every row. Update any script or integration that read the whole list from one call; dropdown data is at `…/options`.
- **Audit history leaves the live table after the plan's window (DATA-11), multi-tenant plans only.** Self-hosted installs keep everything online (`audit_online_months` is unlimited) unless you change it. On SaaS plans, the first monthly `audits:archive` run moves older months to archive files; run `php artisan audits:archive --dry-run` first to see what will move. Optional: `audits:partition --enable` per firm on MySQL/MariaDB (rebuilds the table; maintenance window). See docs/ops/AUDIT_RETENTION.md.
- **Multi-tenant only: the `database` queue moves to the control plane (TEN-2).** Jobs and failed jobs are stored in the control-plane database instead of each firm's. Before upgrading, let workers drain the queue (`php artisan queue:work --stop-when-empty`), since jobs still waiting in firm databases are not moved. Set `DB_QUEUE_CONNECTION` to keep a different connection. Firms placed on a cell with a queue lane need a worker on that lane (`queue:work --queue=<lane>`).
- **Trials now end (PLAT-13), multi-tenant only.** A subscription on the free `trial` plan used to renew free every month; now it lapses at the end of its period and the firm becomes read-only (reads and exports keep working) until a plan is chosen. Firms that never convert are offboarded `BILLING_TRIAL_OFFBOARD_AFTER_DAYS` (default 60) after lapsing; set it to 0 to turn that off. Before upgrading, list them with `select t.slug, s.period_end from subscriptions s join tenants t on t.id = s.tenant_id where s.plan = 'trial' and s.status = 'trialing'` and move any you want to keep to a paid plan.
- **Self-service signup (PLAT-13)** is off until `TENANCY_SIGNUP_HOST` is set. It also needs `TENANCY_BASE_DOMAIN`, a wildcard DNS name and certificate for it, a working mailer, and the scheduler running `billing:run`. See docs/ops/SIGNUP.md.
- **Conflict checks (FUN-9).** `app:upgrade` (and the fleet migrator) queue `BackfillMatterParties`, which copies every matter's opposing party into the new parties register. Run a queue worker, or keep the default `sync` queue. New permissions `run-conflict-checks` and `manage-conflicts` are added to the built-in `admin` role. Grant `run-conflict-checks` to custom roles that open clients or matters, otherwise the web app skips the check for them. Checks are advisory until a firm turns on "require a cleared conflict check" (Conflicts page).
- **Web build (ENG-13): Vite replaces Laravel Mix.** Assets now live in `public/build` (with `public/build/manifest.json`), no longer `public/js`, `public/css` and `public/mix-manifest.json`. Release bundles and the Docker image already contain them. If you build on the server, run `npm ci && npm run build`. If your web server has rules for `/js` or `/css`, add `/build/` (hashed files: cache for a year) and keep `/sw.js` uncached. The old `public/js` and `public/css` folders can be deleted after the upgrade.
- **Mobile web app (FUN-19).** No schema change. New public files `public/sw.js`, `public/offline.html`, `public/images/pwa/*` and the route `/manifest.webmanifest`. The service worker needs HTTPS. If a reverse proxy sets cache headers, keep `sw.js` uncached (`Cache-Control: no-cache`) so updates reach devices promptly.
- **Templates and e-signature (FUN-14).** New tables `document_templates`, `signature_requests`, `signature_signers`. New permission `manage-document-templates` is added to the built-in `admin` role. Signing links go out by email (configure the mailer and run a queue worker for queued mail) and/or SMS. Signers open `https://<firm-host>/sign/<link>`.
- **Email filing (FUN-15).** New tables `matter_emails`, `matter_email_attachments` and a nullable `cases.email_token`. Uploading `.eml` files works at once. Filing by address needs an inbound mail domain and provider (`EMAIL_INGEST_DOMAIN`, `EMAIL_INGEST_SECRET`); see docs/EMAIL_FILING.md.
- **Calendar (FUN-16).** Nullable columns on `hearings` (time, length, courtroom, judicial officer, e-filing reference) and new tables `calendar_feeds`, `calendar_connections`, `calendar_event_links`. The scheduler runs `calendar:sync` every 15 minutes. Direct Google / Microsoft sync stays off until an OAuth app is configured (`GOOGLE_CALENDAR_*`, `MICROSOFT_CALENDAR_*`, or per firm under Integrations) with `CALENDAR_OAUTH_REDIRECT` registered as its redirect URI; subscription links need nothing. See docs/CALENDAR.md.
- **Document search (FUN-8).** New table `document_texts` (full-text index on MySQL/MariaDB). `app:upgrade` (and the fleet migrator) queue `BackfillDocumentText`, which reads every existing document; run a queue worker, because with the `sync` queue the upgrade does it inline and a large firm may take a while. PDFs and OCR need `poppler-utils` and `tesseract-ocr` (included in the Docker image; install them on bare metal), otherwise those documents are marked not searchable until read again. See docs/DOCUMENT_SEARCH.md.
- **E-billing (FUN-13).** Nullable columns only: UTBMS codes on `time_entries`, `invoice_items`, `expenses`; `clients.ebilling_client_id`, `cases.client_matter_id`, `users.timekeeper_class`. No permission changes. Nothing changes for invoices until someone codes their work; existing API clients that do not send the new fields keep their values.
- **Client portal (FUN-10).** New tables only (`portal_accounts`, `portal_login_codes`, `portal_sessions`, `portal_documents`, `portal_messages`). Nobody can sign in until the firm gives a client access. New permission `manage-client-portal` is added to the built-in `admin` and `advocate` roles; custom roles are not changed. The portal is a plan feature (`client_portal`: Professional and Enterprise, always on self-hosted) and needs a working SMS provider. Sign-in at `https://<firm-host>/portal` is exempt from read-only mode, like staff sign-in.
- **Online payment (FUN-11).** New tables `invoice_payment_links` and `online_payment_attempts`. Nothing is offered until a firm saves M-Pesa or Stripe credentials (entered by the operator in the console, or `MPESA_COLLECT_*` / `STRIPE_COLLECT_*` in `.env` for self-hosted). For card payments add a Stripe webhook to `https://<firm-host>/api/v1/pay/callback/stripe`. The M-Pesa callback URL is set per payment; Safaricom must be able to reach the firm host over HTTPS. Staff need `create-payments` to send links.
- **Partner reports (FUN-17).** No schema change. New permission `view-partner-reports` is added to the built-in `admin` role.
- **Capacity (ENG-27).** A firm database has 86 tables. On a multi-tenant cell, set `table_open_cache` and `table_definition_cache` to at least firms × 20 and `open_files_limit` to twice that, or keep the cell at about 200 firms (`cells update <cell> --capacity=200`). Run `php artisan capacity:report` after upgrading; see docs/ops/CAPACITY.md.
- **Analytics warehouse (ENG-26).** Off until `WAREHOUSE_ENABLED=true` (docs/ops/WAREHOUSE.md). The scheduler then runs `warehouse:export` nightly. `App\Warehouse\WarehousePurgeStep` joins `tenancy.purge_steps` by default. If you override that list, keep it and `App\Search\SearchPurgeStep`.
- **Search engine (ENG-19).** Optional; search stays SQL until `SEARCH_ENGINE=meilisearch` with `MEILISEARCH_HOST` and `MEILISEARCH_KEY` (Helm `search.*`). Then run `php artisan search:reindex` once (every firm in multi-tenant mode). The new purge step `App\Search\SearchPurgeStep` is in `tenancy.purge_steps` by default; keep it if you list your own steps. See docs/SEARCH.md.
- **Queue lanes (ENG-20).** Heavy jobs now go to a `bulk` lane (`<lane>-bulk` for a cell with its own lane). **Workers must listen on it**: the Docker image and Helm chart do (`default,bulk`); a hand-run worker needs `php artisan queue:work --queue=default,bulk`, otherwise exports and document reading never run. Set the worker `--timeout` to at least 3700 (exports may run an hour). `QUEUE_RETRY_AFTER` now defaults to 3800 s. Optional: Redis for cache, sessions and queue (docs/ops/QUEUES.md); drain the old queue before switching `QUEUE_CONNECTION`.
- **Direct uploads (ENG-22).** New table `document_uploads`. With S3-compatible storage, the web app now uploads documents straight to the bucket. **Add a CORS rule to the bucket allowing `POST` from the firm hosts** (docs/ops/DIRECT_UPLOADS.md), otherwise uploads fail; or set `DOCUMENTS_DIRECT_UPLOADS=false` until you have. The scheduler runs `documents:prune-uploads` hourly. Installs on local storage are unaffected.
- **Read replica (ENG-23).** Optional; nothing changes until it is configured. Reports and the dashboard read from a replica: `DB_REPLICA_HOST` for one firm, `php artisan cells update <cell> --replica-host=` for multi-tenant cells (control plane gains nullable `cells.replica_host` and `replica_port`). `REPORTS_DB_CONNECTION` still works. A replica that is unreachable, stopped or more than `DB_REPLICA_MAX_LAG` seconds behind is skipped. Give the replica account `REPLICATION CLIENT` (MySQL) or `REPLICA MONITOR` (MariaDB) so the screens can show lag. See docs/ops/READ_REPLICA.md.
- **Trust reconciliation (FUN-12).** New tables only; the trust ledger is untouched. New permission `reconcile-trust-accounts` is added to the built-in `admin` role. Firms on plans with trust accounting can start reconciling from their next statement.
- **Offices and practice groups (FUN-18).** New tables and nullable columns on `users` and `cases`. Nothing changes until a firm creates an office or group. New permission `manage-organisation` is added to the built-in `admin` role.
- **New permission `manage-subscription`** (choose the firm's plan) is added to the built-in `admin` role. Custom roles are not changed.
- **New database tables** (all additive; existing tables are untouched): see the migrations list printed by `php artisan app:upgrade --dry-run`.
- New optional features, off or inert until configured: matter-level access (`MATTER_ACCESS=restricted`; default `firm` = no change), SSO and the firm MFA policy, the public API and webhooks (plan feature `api_access`), legal holds and retention (nothing is purged until a firm sets a period and enables it), support access (firm policy decides), billing (multi-tenant only; prices in `config/billing.php` are placeholders).
- New unauthenticated endpoints: `/health/live`, `/health/ready`, `/status`, `/status.json`. They reveal component states only. Block them at the edge if you do not want them public.

## Required actions

1. `php artisan release:notes` and read the entries for the versions in between.
2. `php artisan app:upgrade --dry-run`, then `php artisan app:upgrade --backup --maintenance`. In multi-tenant mode this migrates the control plane and then every firm; a firm that fails is reported and the run can be repeated.
3. Check the scheduler is running (Before you upgrade).
4. Multi-tenant: have every platform staff member enrol MFA (`POST /api/platform/mfa/setup`, then `/mfa/enable`), or set `PLATFORM_MFA=optional` for now. Lost authenticator: `php artisan platform:staff mfa-reset <email>`.
5. Optional: grant the new permissions to custom roles that need them.
6. Optional: move secrets to files (`FOO_FILE=/path`) and run `php artisan secrets:check` (docs/ops/SECRETS.md).
7. If you set `SSO_SUCCESS_REDIRECT`, point it at `/login?sso=complete` (the new default): the login page now finishes SSO sign-ins. The web app supports the two-step MFA login, SSO and enforced enrolment, so firms can turn on the MFA policy and SSO from Settings → Security (docs/SSO.md).

## After you upgrade

- `php artisan app:version` prints the new version; `GET /health/ready` returns 200; `/status` shows components operational after about two minutes.
- `php artisan release:notes` shows nothing left to do.

## Rollback

Schema changes are expand-only: the previous release keeps running on the new schema (within one minor). Switch back with `deploy/rollback.sh`, or redeploy the previous image,
then re-run `app:upgrade` for that version. `app:upgrade` refuses to run code more than one minor older than the schema. Data written by new features (holds, DSAR records, API keys,
billing records) is simply not read by the old release. Nothing in this upgrade deletes data.
